# Security

## Reporting a vulnerability

Open a GitHub issue, or contact the repository owner directly for anything
sensitive. This is a portfolio project with no production deployment and no
real users, so there is no formal disclosure timeline.

## What this project deliberately does not do

These are enforced in code, not just documented:

| Rule | Where it is enforced |
|---|---|
| Never connects to a real airline, GDS, or payment system | `BookingProvider` declares no write method; `tests/test_adapters.py` fails if one is added |
| Never connects to a real mailbox or calendar | `Settings` rejects any provider value other than `mock` |
| Never sends email without human approval | `EmailProvider.send_reply` requires a non-empty `approved_by` argument |
| Never runs a high-risk workflow step unattended | The engine halts at `HUMAN_APPROVAL` and cannot proceed without `resume(approved_by=...)` |
| Never exposes a secret over HTTP | `/health` and `/api/system` serialise only `Settings.redacted()` |
| Never shows a stack trace to a user | Global handlers in `apps/api/app/errors.py` return a fixed safe payload |

## Secrets

- Configuration comes from environment variables only. There are no hard-coded
  credentials.
- `.env` is gitignored; `.env.example` holds empty placeholders and is the only
  env file in the repo.
- CI fails the build if a `.env` file or an API-key-shaped string is committed.
- API keys stay server-side. Every page is a React Server Component, so no key
  is ever serialised into a browser payload.
- A key pasted into the "bring your own key" field is used for that request and
  is not persisted.

## Data

All data in this repository is synthetic, generated by
`scripts/generate_demo_data.py`. No real person, travel agency, booking, or
email appears anywhere. Names, agency names, and email addresses are invented,
and the domains use the reserved `.test` TLD.

The activity log records metadata about AI calls — model, duration, tokens,
cost, and whether a human approved — but deliberately not prompt or response
bodies (CLAUDE.md Section 22).

## If a key is exposed

1. Revoke it in the provider's console immediately.
2. Remove it from the working tree and rotate any that shared its scope.
3. If it was committed, treat the history as compromised — rewriting history is
   not sufficient on a repository that has been pushed.
